# Как устроен Sketch Duel

Разбор для человека, который раньше не работал с нейросетями. Читается сверху вниз: сначала общая картина, потом каждый слой по отдельности, в конце — как отлаживать и что менять.

---

## 1. Что вообще происходит

В проекте две игры.

**Режим 1.** Тебе выпадает слово, ты рисуешь мышкой или пальцем. Пока рисуешь, маленькая нейросеть смотрит на холст и говорит, что она там видит. Если она угадала загаданное слово — раунд выигран.

**Режим 2.** Холст сам рисует картинку штрих за штрихом, а ты угадываешь по вариантам ответа. Важная деталь: **здесь ничего не генерируется нейросетью**. Это запись того, как рисунок рисовал живой человек — из открытого датасета Google. Мы просто проигрываем сохранённые координаты по порядку, как видеозапись.

**Бэкенда нет вообще.** Нет сервера, нет базы, нет API. Есть папка со статическими файлами: HTML, JS, CSS, файл с весами сети и файлы с записями рисунков. Их отдаёт любой веб-сервер. Вся «нейросеть» работает у тебя в браузере на JavaScript.

Это не упрощение ради лени — так честнее и быстрее: рисунок не улетает на сервер, ответ приходит за доли миллисекунды, и хостинг стоит ноль.

## 3. Что такое нейросеть, если совсем на пальцах

Забудь слово «нейрон». По сути нейросеть — это **большая формула с настраиваемыми числами**.

Представь, что тебе надо отличать кошек от домов по картинке. Ты берёшь все пиксели картинки, каждый умножаешь на какое-то число, всё складываешь, и если сумма большая — говоришь «кошка». Числа, на которые ты умножаешь, называются **весами**. Их никто не придумывает руками — их **подбирают автоматически** на тысячах примеров.

Вот и всё. Дальше только детали: сколько таких умножений, в каком порядке, и как именно подбирать числа.

### Наша сеть целиком

```
784 числа  →  256 чисел  →  128 чисел  →  100 чисел
 (пиксели)      (слой 1)      (слой 2)     (ответы)
```

- **784** — это картинка 28×28 пикселей, вытянутая в один длинный список. Каждое число — яркость пикселя от 0 (белое) до 1 (чёрное).
- **100** — по одному числу на каждое слово, которое сеть знает. Чем больше число, тем увереннее она в этом слове.
- **256 и 128** посередине — промежуточные, «скрытые» слои. Их размер выбран на глаз: больше — умнее, но тяжелее и медленнее.

Каждая стрелка — это умножение матрицы на вектор. Например, первая стрелка: у нас 784 входа и 256 выходов, значит нужно 784 × 256 = 200 704 весов. Всего в сети около 240 тысяч чисел. Это очень мало по нынешним меркам (в больших моделях их миллиарды), поэтому файл весит 300 КБ и грузится мгновенно.

### Что происходит внутри одного слоя

Код в `shared/model.js`, функция `predict`. Она делает ровно три вещи для каждого слоя:

```js
// 1. Для каждого выходного нейрона: сумма всех входов, умноженных на его веса
let sum = L.b[o]                                   // b — «смещение», просто константа
for (let i = 0; i < L.inN; i++) sum += cur[i] * L.w[base + i]
out[o] = sum

// 2. ReLU: всё отрицательное превращаем в ноль
if (out[o] < 0) out[o] = 0
```

**Зачем ReLU?** Если бы мы просто умножали и складывали, три слоя подряд схлопнулись бы в один — математически это была бы одна большая матрица. ReLU (`max(0, x)`) ломает эту линейность, и только благодаря ей сеть может выучить что-то сложнее прямой линии. Это самая простая нелинейность из существующих, и она отлично работает.

### Softmax: из чисел в проценты

На выходе последнего слоя — 100 произвольных чисел вроде `[3.2, -1.4, 8.9, ...]`. Их надо превратить в вероятности, которые в сумме дают 100%. Этим занимается **softmax**:

```js
// возводим e в степень каждого числа и делим на сумму всех
const e = Math.exp(cur[i] - max)   // вычитаем max, чтобы не переполнилось
cur[i] = e / sum
```

После этого `[3.2, -1.4, 8.9]` превращается во что-то вроде `[0.003, 0.000, 0.996]` — «на 99.6% уверена в третьем варианте». Именно эти проценты ты видишь в панели «ИИ видит».

## 4. Как рисунок превращается в 784 числа

Это самая недооценённая часть проекта, и именно здесь чаще всего ломаются такие модели.

Файл `shared/sketch.js`, функция `rasterize`. Она делает так:

1. **Собирает рамку.** Находит крайние точки рисунка — левую, правую, верхнюю, нижнюю.
2. **Вписывает в квадрат.** Масштабирует рисунок так, чтобы он занял 24×24 из 28×28, с полями по краям. Пропорции сохраняются, чтобы длинный банан не превратился в круглое яблоко.
3. **Рисует крупно, потом уменьшает.** Сначала рисует линии в разрешении 112×112 мягким «пером», затем усредняет блоки 4×4 в один пиксель. Это даёт сглаживание — линии получаются с полутонами, а не рваными ступеньками.

Побочный эффект такой нормализации: **сети всё равно, где и какого размера ты нарисовал**. Маленький домик в углу и огромный на весь холст дадут почти одинаковые 784 числа.

### Почему это самое важное место в проекте

Нейросеть — тупой сопоставитель. Она узнаёт только то, что видела **в точно таком же виде**. Если при обучении картинки готовили одним кодом, а в браузере — другим, пусть даже отличающимся на толщину линии, точность падает вдвое, и все думают, что «модель плохая».

Поэтому `shared/sketch.js` вызывается **из двух мест сразу**:

- из `scripts/fetch-data.mjs`, когда готовится обучающая выборка;
- из браузера, когда ты рисуешь.

Один и тот же файл, одна и та же функция. Расхождение физически невозможно.

Проверить можно так — увидишь, как сеть видит твой рисунок:

```js
import { rasterize, bitmapToAscii } from './shared/sketch.js'
console.log(bitmapToAscii(rasterize(strokes)))
```

## 5. Как сеть обучили

Файл `scripts/train.mjs`. Обучение написано на чистом JavaScript — ни Python, ни PyTorch, ни нативных библиотек. Это осознанный выбор: весь проект собирается одной командой `npm run data:all`, без установки чего-либо кроме `npm install`.

### Откуда данные

[Google QuickDraw](https://github.com/googlecreativelab/quickdraw-dataset) — 50 миллионов рисунков, которые люди рисовали в браузерной игре Google. Открытая лицензия. Каждый рисунок хранится как список штрихов, каждый штрих — список координат:

```json
{"word":"apple","recognized":true,"drawing":[[[95,79,68],[95,60,40]], ...]}
```

Полные файлы весят по 50–150 МБ на категорию, а нам нужны первые пара тысяч рисунков. Поэтому `fetch-data.mjs` качает их **кусками через HTTP Range** — то есть просит «отдай мне первые 4 мегабайта файла», а не файл целиком. 100 категорий скачиваются за несколько минут вместо часов.

Берём только рисунки с `recognized: true` — те, которые угадала оригинальная гугловская модель. Метки чище, и в режиме 2 они выглядят приличнее.

### Обучающая выборка

На каждую категорию берём 1800 рисунков и делаем из каждого **две картинки**: обычную и слегка искажённую — повёрнутую на случайный небольшой угол, сдвинутую, чуть другого размера. Это называется **аугментация**. Смысл: если сеть видела только идеально выровненные примеры, она растеряется от кривого рисунка мышкой. Показывая ей искажённые копии, мы заранее учим её не обращать внимания на такие мелочи.

Итого 100 категорий × 1800 × 2 = **360 000 обучающих примеров**. Плюс 250 примеров на категорию откладываются в сторону и **при обучении не показываются** — это «отложенная выборка», по ней потом честно измеряют точность.

### Сам процесс обучения

Обучение — это цикл, который повторяется много раз:

1. **Взять пачку из 128 картинок** (батч).
2. **Прогнать через сеть** — получить ответы.
3. **Посчитать ошибку.** Насколько ответы разошлись с правильными метками. Мера ошибки называется *cross-entropy loss*: чем увереннее сеть ошиблась, тем сильнее её штрафуют.
4. **Посчитать, в какую сторону крутить каждый вес**, чтобы ошибка стала меньше. Это и есть знаменитое *обратное распространение ошибки* (backpropagation) — функция `backwardLinear` в коде. По сути школьная производная, применённая по цепочке от конца сети к началу.
5. **Немного подвинуть все веса** в эту сторону. Насколько немного — определяет *скорость обучения* (learning rate). Алгоритм подкрутки — **Adam**, он умнее простого шага: помнит, куда двигался раньше, и для каждого веса подбирает свой размер шага.

Один полный проход по всем 360 тысячам примеров называется **эпохой**. Мы делаем 11 эпох. Смотреть за обучением можно прямо в логе:

```
эпоха  1/11  loss=1.3090  val top1=78.08%  top3=91.50%
эпоха  2/11  loss=0.8572  val top1=81.24%  top3=93.64%
```

- `loss` — ошибка, должна падать. Если не падает — что-то сломано.
- `val top1` — доля случаев, когда **первый** ответ сети правильный, на отложенной выборке.
- `val top3` — доля случаев, когда правильный ответ попал **в тройку**.

Если `loss` падает, а `val top1` начинает расти в обратную сторону — это **переобучение**: сеть заучила примеры наизусть вместо того, чтобы понять суть. Против этого в коде есть два средства: **dropout** (на каждом шаге случайные 15% нейронов отключаются, чтобы сеть не полагалась на кого-то одного) и та самая аугментация.

Скрипт сохраняет **лучшую по точности** версию весов, а не последнюю, и делает это после каждой улучшившейся эпохи — обрыв обучения не обнуляет прогон.

### Квантование: как ужать веса в 4 раза

Веса — это числа с плавающей точкой, каждое занимает 4 байта. 240 тысяч весов = почти мегабайт. Многовато для загрузки на телефоне.

Приём называется **int8-квантование**: вместо 4 байт храним 1 байт (число от −127 до 127) плюс один общий множитель на каждый выходной нейрон.

```js
const sc = max / 127                       // множитель
q[i] = Math.round(w[i] / sc)               // упаковали в байт
// в браузере обратно:
w[i] = q[i] * sc
```

Точность при этом теряется, но крохи: `verify.mjs` отдельно это проверяет и показывает разницу до и после — она составила 0.04%. Файл при этом похудел в четыре раза.

## 6. Как модель попадает в браузер

`public/model/` содержит два файла:

- **`model.json`** — описание: сколько слоёв, какого размера, список слов, по каким смещениям в бинарнике что лежит.
- **`model.bin`** — сами числа, подряд, без разделителей.

Композабл `app/composables/useClassifier.js` скачивает оба, разворачивает int8 обратно во `Float32Array` и держит модель в памяти. Дальше:

```js
const { top, probOf } = clf.analyze(strokes, 3)
// top      → [{ ru: 'дом', p: 0.97 }, ...]
// probOf   → probOf('cat') вернёт вероятность конкретного слова
```

Один прогон занимает меньше миллисекунды, поэтому распознавать можно хоть 60 раз в секунду. Модель грузится один раз на всё приложение — `state.promise` в композабле гарантирует, что даже при быстром переключении страниц запрос уйдёт только один.

## 7. Как устроен сайт

**Nuxt 4** — надстройка над Vue 3. Здесь она нужна ради трёх вещей: файловый роутинг (`app/pages/draw.vue` автоматически становится адресом `/draw`), автоимпорт компонентов и композаблов, и генерация статики командой `npm run generate`.

### Холст для рисования — `SketchPad.vue`

Штрихи хранятся **не в пикселях экрана**, а в «виртуальных» координатах 0..1000. Холст всегда квадратный, поэтому пересчёт однозначный. Это значит, что при изменении размера окна рисунок просто перерисуется в новом масштабе и ничего не поедет.

Технические тонкости, каждая из которых была реальной проблемой:

- `touch-action: none` — иначе на телефоне вместо рисования страница будет скроллиться.
- `setPointerCapture` — чтобы штрих не обрывался, если палец вышел за край холста. Обёрнут в `try/catch`: без этого одно исключение оставляло указатель «захваченным» навсегда и холст молча переставал рисовать.
- `getCoalescedEvents()` — браузер копит промежуточные точки между кадрами; если их забрать, линия получается плавнее.
- Сглаживание квадратичными кривыми через середины отрезков — иначе линия выглядит как ломаная из палок.
- `devicePixelRatio` — на ретине холст рисуется в двойном разрешении, иначе всё мыльное.

### Проигрыватель — `ReplayCanvas.vue`

Собирает из рисунка «таймлайн»: список отрезков с их длинами плюс искусственные паузы между штрихами (имитация отрыва карандаша). Дальше по `requestAnimationFrame` показывает ту часть таймлайна, которая уже «нарисована». Скорость подбирается от общей длины линий, чтобы простой рисунок не проскакивал мгновенно, а сложный не тянулся вечно.

### Состояние

- `useClassifier()` — модель, одна на всё приложение.
- `useReplay()` — рисунки для режима 2, подгружаются по одной категории и кэшируются.
- `useGameSettings()` — выбранная сложность, сохраняется в `localStorage`.

## 8. Почему сеть специально сделана глупее

Изначально она угадывала почти мгновенно, и играть было неинтересно. Сложность (в `shared/categories.js`) крутит четыре ручки — **саму модель при этом не трогает**:

| Ручка | Что делает |
|---|---|
| `maxTier` | из скольких слов выбирается загадка: 30 / 65 / 100 |
| `winP` | какая уверенность засчитывается: 45% / 62% / 75% |
| `think` | как часто сеть вообще смотрит на холст: раз в 400 / 550 / 700 мс |
| `holdFrames` | сколько проверок подряд она должна быть уверена: 2 / 3 / 3 |

Последние две — самые важные для ощущения. Раньше сеть пересчитывала ответ после каждого движения мыши и срабатывала на первом же удачном кадре. Теперь она «поглядывает» с паузами и должна узнать слово несколько раз подряд — то есть рисунок должен быть устойчиво похожим, а не случайно совпасть на мгновение.

Плюс само расширение с 30 до 100 слов сделало задачу честно труднее: чем больше вариантов, тем ниже уверенность в каждом.

## 9. Как отлаживать

**Сеть не узнаёт то, что явно нарисовано.** Первым делом посмотри, что она вообще видит:

```js
import { rasterize, bitmapToAscii } from '~~/shared/sketch.js'
console.log(bitmapToAscii(rasterize(pad.getStrokes())))
```

Если в ASCII-картинке каша — проблема в растеризации или в самих штрихах, а не в сети.

**Проверить всю цепочку целиком:**

```bash
npm run verify
```

Скрипт гоняет **ровно тот код, что исполняется в браузере**, на отложенной выборке и проверяет 18 вещей: точность до и после квантования, инвариантность растеризатора к масштабу и сдвигу, целостность бинарника, валидность реплеев, обобщение на невиданные рисунки.

**Посмотреть по классам, что хуже всего узнаётся** — это печатает `train.mjs` в конце:

```
Хуже всего узнаются: tree 75%, lightning 77%, pizza 77%
```

**Проверить конкретную фигуру прямо в консоли браузера** (dev-режим):

```js
const base = '/_nuxt/@fs/D:/MeProjects/sketch-duel/'
const S = await import(base + 'shared/sketch.js')
const M = await import(base + 'shared/model.js')
const model = M.loadModel(
  await (await fetch('/model/model.json')).json(),
  await (await fetch('/model/model.bin')).arrayBuffer()
)
M.topK(model, M.predict(model, S.rasterize(мои_штрихи)), 5)
```

## 10. Что можно менять

**Добавить слово.** Дописать строчку в `shared/categories.js` (имя должно точно совпадать с категорией QuickDraw) и перезапустить `npm run data:all`. Проверить, что имя существует, можно так:

```bash
curl -sI "https://storage.googleapis.com/quickdraw_dataset/full/simplified/panda.ndjson" | head -1
```

**Сделать сеть точнее.** Крутится через переменные окружения:

```bash
N_TRAIN=3000 AUG_COPIES=2 npm run data:fetch   # больше данных
```

Ожидаемый потолок для такой архитектуры — примерно 80% top-1 на 100 классах. Чтобы прыгнуть выше, нужна **свёрточная сеть** (CNN): она смотрит на локальные участки картинки, а не на все 784 пикселя сразу, и на подобных задачах даёт 92–94%. Это заметно больше работы, потому что свёртки придётся либо писать руками, либо тащить в проект TensorFlow.js.

**Поменять ощущение игры** — всё в `DIFFICULTIES` в `shared/categories.js`, менять можно без перезапуска обучения.

**Поменять внешний вид** — `app/assets/scss/_tokens.scss`. Все цвета, скругления и тени в одном месте.

## 11. Честные ограничения

- Сеть узнаёт **только 100 слов**. Нарисуешь что-то другое — она всё равно назовёт одно из ста, просто с низкой уверенностью. Это не баг, так устроен классификатор.
- Она смотрит на **картинку 28×28**, а не на порядок штрихов. Модели, которые учитывают ещё и последовательность рисования (RNN), точнее, но сложнее.
- В режиме 2 нейросеть **ничего не рисует** — это воспроизведение человеческих рисунков. Настоящую генерацию даёт `sketch-rnn` от Magenta, её можно прикрутить отдельным режимом.
- Счёт живёт в памяти вкладки: обновил страницу — обнулился. Лидерборд потребовал бы бэкенда, которого специально нет.
